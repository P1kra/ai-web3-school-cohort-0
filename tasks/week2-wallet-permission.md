# Week 2｜Permission Strategy for Agent-Initiated On-Chain Actions

## 问题定义

当 AI Agent 获得链上操作能力时，核心安全问题是：**如何让 Agent 能执行必要的链上操作，同时确保人类保留最终控制权？**

## 权限分层模型

### Layer 1: 资源隔离
Agent 永远不直接持有主钱包私钥。所有 Agent 操作通过专用子账户或 Session Key 完成。

```
主钱包 (人类控制，冷存储)
    │
    ├── Agent 操作账户 (Smart Account, 有限资金)
    │       │
    │       ├── Session Key A (API 支付专用)
    │       ├── Session Key B (数据采购专用)
    │       └── Session Key C (测试/开发专用)
    │
    └── 储备账户 (人类手动操作)
```

### Layer 2: 策略控制矩阵

| 操作类型 | Session Key | 预算上限 | 时间窗口 | 频率限制 | 人工审批 |
|----------|------------|----------|----------|----------|----------|
| API 调用付费 | Key A | $10/天 | 永久 | 100次/天 | <$1 免审批 |
| 数据采购 | Key B | $50/次 | 每周一 | 5次/周 | 全部审批 |
| 合约测试交互 | Key C | 0.01 ETH/天 | 30天 | 无限制 | 免审批 |
| Token 转账 | 禁止 | — | — | — | 必须人工 |

### Layer 3: 时间锁 + 可撤回

- **时间锁**：大额操作（>$50）设置 30 分钟冷静期，期间人类可取消
- **紧急冻结**：一键暂停所有 Agent 操作权限
- **自动过期**：Session Key 最长有效期 7 天，过期自动失效

## 签名策略

### 方案对比

| 方案 | 安全模型 | 优点 | 缺点 |
|------|----------|------|------|
| EOA 私钥直接签名 | 私钥 = 完全控制 | 兼容性最好 | Agent 失窃 = 资产全丢 |
| MPC 分片签名 | 多方计算 | 无私钥单点风险 | 需要信任 MPC 节点 |
| Smart Account + Session Key | 合约控制 | 可编程权限、可撤销 | 需要合约钱包部署 |
| Intent + Solver | 意图表达 | 最大灵活性 | 生态不成熟 |

### 推荐方案：Smart Account + Session Key

具体实现：
1. 部署 Safe 智能账户作为 Agent 操作账户
2. 为每个用途生成独立的 Session Key
3. Session Key 通过 Safe 模块限制权限（目标合约白名单、金额上限）
4. 人类通过 Safe 多签保留超级管理员权限

## 人工确认策略

### 自动放行（无需人类介入）
- 金额 < $1 且接收方在白名单
- 规定频率内的重复性支付
- 测试网操作

### 推送通知（告知但不阻塞）
- $1-$50 的支付
- 新白名单地址首次支付

### 强制审批（阻塞直到人类确认）
- 金额 > $50
- 不在白名单的接收方
- 更改策略配置
- 提取资金到外部地址

## 异常检测

- 短时间内支付金额突然增大 5 倍以上
- 同一接收方 1 小时内超过 50 笔
- 深夜（本地时间 2-6am）的大额操作
- 检测到 → 自动暂停 + 推送告警
