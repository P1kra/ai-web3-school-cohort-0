# Week 2｜Governance and Coordination Workflow Sketch

## 问题

当多个 AI Agent 在同一个链上生态中协作时，如何协调它们的行为？谁来制定规则，谁来执行，谁来解决争议？

## 治理-协调三层模型

### Layer 1: 协议规则（Protocol Rules）
不可变的链上规则，所有 Agent 必须遵守。

- **支付标准**：x402 协议定义支付格式
- **身份标准**：Agent 必须注册链上身份（DID）才能参与
- **争议窗口**：每笔支付有 24h 争议期，期间可冻结

### Layer 2: 策略配置（Policy Configuration）
人类为每个 Agent 设定的个性化规则。

- **预算分配**：每个 Agent 多少钱
- **权限范围**：能调哪些合约
- **风险偏好**：激进（自动）vs 保守（多审批）

### Layer 3: 社区治理（Community Governance）
人类社区对 Agent 生态的集体决策。

- **白名单维护**：哪些服务商可信
- **费率协商**：Agent 间服务定价标准
- **争议仲裁**：Agent 间纠纷的人类裁决

## 治理流程

```
人类设定策略（一次性）
    │
    ▼
Agent 自主运行（日常）
    │
    ├── 正常：支付完成 → 日志记录 → 周报汇总
    │
    ├── 争议：支付被质疑 → 24h 冻结 → 多签仲裁 → 释放/退款
    │
    └── 升级：策略需要调整 → 提案 → 人类投票 → 更新策略
```

## 协调机制

### Agent-to-Agent 协调

| 场景 | 协调方式 | 示例 |
|------|----------|------|
| 服务发现 | 链上注册表 | Agent A 需要翻译服务 → 查注册表找到 Agent B |
| 价格协商 | 订单簿 / RFQ | Agent A 询价 → Agent B 报价 → 接受/拒绝 |
| 支付结算 | x402 + USDC | 服务完成 → 402 支付 → 链上确认 |
| 争议解决 | 多签委员会 | 服务不满意 → 冻结资金 → 3/5 多签裁决 |

### 人类在循环中的角色

1. **策略制定者**：设定 Agent 的行为边界（一次性）
2. **异常处理者**：处理自动系统无法裁决的争议
3. **升级决策者**：调整策略、增减预算、更新白名单
4. **审计者**：定期检查 Agent 行为是否符合预期

## 与现有治理方案的对比

| 特征 | DAO 治理 | Agent 治理 |
|------|----------|-----------|
| 决策频率 | 周/月 | 秒/分钟 |
| 决策颗粒度 | 协议升级、财库管理 | 单笔支付、API 调用 |
| 人类参与 | 投票（低频） | 策略设定（一次性）+ 异常处理 |
| 自动化程度 | 低（需人投票） | 高（策略驱动自治） |

## 本方向的特殊性

Agent Payment Commerce 赛道的治理需求与其他方向不同：
- **不需要复杂投票**：大部分决策是二元判断（付/不付）
- **策略优先于民主**：一个人的 Agent，不需要社区投票决定能不能花 5 USDC
- **争议解决是瓶颈**：Agent 间纠纷如何低成本仲裁？这是未解决的真问题
