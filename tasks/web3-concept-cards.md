# Web3 基础概念卡片

## 1. 密码学基础
- **是什么：** 哈希、公私钥、数字签名——Web3 安全的数学地基。
- **为什么重要：** 没有密码学就没有"你的资产只有你能动"。
- **安全提醒：** 私钥=所有权，公钥=地址，签名=证明"这操作是我同意的"。私钥丢了没人能帮你找回——不像银行可以重置密码。

## 2. 钱包
- **是什么：** 不只是存币工具，而是身份入口+签名器。
- **为什么重要：** 不管理私钥，任何链上操作都做不了。
- **常见误区：** 钱包不是"存"币的地方——币在链上，钱包只存私钥。助记词=私钥的另一种形态，同样不能给任何人。
- **安全提醒：** EOA（普通地址）→ 一把钥匙全部权限；智能账户 → 可以多人、设规则、设限额，更适合 Agent。

## 3. 智能合约
- **是什么：** 跑在链上的代码，不可篡改，自动执行规则。
- **为什么重要：** Web3 的规则引擎——DeFi、NFT、DAO 全跑在合约上。
- **常见误区：** "代码即法律"不代表合约一定安全。部署前必须审计，因为一旦上链就不能偷偷改。
- **安全提醒：** 每个合约调用都要看清授权范围——你签名时可能给了合约无限额度的转账权限。

## 4. 网络与共识
- **是什么：** 区块链怎么让所有人对同一份账本达成一致。
- **为什么重要：** 去中心化的底层保障——不能有人说了算。
- **常见误区：** 不是所有链都一样。L1 做安全结算（贵但稳），L2 做速度和便宜（快但依赖 L1）。
- **边界：** Agent 选链要考虑 Gas 成本和确认时间——发一笔交易花 $50 就不适合高频操作。

## 5. 账户抽象（AA）
- **是什么：** 把钱包从"一把钥匙一个人"升级成"可编程账户"。
- **为什么重要：** Agent 用钱包的前提——设置额度、时间锁、多签、自动执行。
- **案例：** 传统钱包要么全权限要么没有。AA 可以设"每天最多花 0.1 ETH，只有这个 Agent 能用，超了自动停"。

## 6. DeFi（去中心化金融）
- **是什么：** 跑在链上的金融协议——借贷、交易、质押、收益，不需要银行或券商。
- **为什么重要：** DeFi 是 Web3 最大应用场景，也是 AI Agent 最可能自动化的领域之一。
- **常见误区：** DeFi 不等于没有风险——合约漏洞、预言机操纵、闪电贷攻击都是真实发生过的事故。
- **安全提醒：** 高收益必然伴随高风险。Agent 参与 DeFi 操作必须有硬性额度上限。

## 7. 预言机（Oracle）
- **是什么：** 把链外数据（价格、天气、比赛结果）喂进链上合约的服务。
- **为什么重要：** 链上合约自己不能访问互联网，Oracle 是它看外面的"眼睛"。
- **常见误区：** Oracle 本身可能被攻击——如果价格数据源被篡改，依赖它的 DeFi 协议全部遭殃。
- **边界：** AI Agent 判断数据可信度时，不能只看数据本身，还要看 Oracle 的声誉和去中心化程度。

## 8. 安全（Security）
- **是什么：** 合约、钱包、签名、授权、前端——Web3 攻击面远比传统互联网大。
- **为什么重要：** 在 Web3 犯错没有客服没有退路。每个授权、每笔交易、每次签名都是不可逆的。
- **常见攻击：** 钓鱼网站、假合约授权、私钥泄露、助记词截图——不是一个技术问题，是习惯问题。

---

## ⚠️ 私钥、助记词、签名和授权为什么需要特别谨慎

Web3 和传统互联网最大的区别：**没有管理员能帮你撤销。**

| 东西 | 相当于 | 泄露后果 |
|------|--------|----------|
| **私钥** | 银行卡密码+身份证 | 对方可以转走你所有资产，永远拿不回来 |
| **助记词** | 私钥的人话版 | 同上——12/24 个单词 = 你的整个钱包 |
| **签名** | 你亲笔签字 | 授权合约花你的币、转你的 NFT |
| **授权（approve）** | 你给合约一张空白支票 | 恶意合约可以无限次从你钱包划钱 |

**铁律：**
1. 私钥/助记词不给任何人，不截图，不存云端
2. 签名前看清合约地址和授权额度
3. 测试网先用测试钱包，和主网钱包完全分开
4. 大额操作前先小额测试
